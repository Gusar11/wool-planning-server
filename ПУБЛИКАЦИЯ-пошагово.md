# Публикация Wool & Hornet Planning в интернете

Цель этой инструкции: получить публичную ссылку вида `https://…`, которую можно отправить команде, и все смогут пользоваться инструментом. Локальный запуск вы уже проходили — здесь только про публикацию.

Мы используем **Railway** — платформу, которая сама соберёт проект и выдаст ссылку. В проекте уже лежат нужные файлы (`Dockerfile`, `railway.json`), поэтому Railway всё поймёт автоматически.

Весь путь — три части: загрузить код на GitHub → развернуть на Railway → включить сохранение данных и защиту.

---

## Часть 1. Загрузить код на GitHub

Railway берёт код из GitHub, поэтому сначала кладём папку проекта туда. Без командной строки — через программу с кнопками.

1. Заведите бесплатный аккаунт на https://github.com
2. Скачайте и установите **GitHub Desktop**: https://desktop.github.com
3. Войдите в GitHub Desktop под своим аккаунтом GitHub.
4. Меню **File → Add local repository** → выберите папку `wool-planning-server`.
   - Если появится предложение «create a repository here» — нажмите его (**Create a repository**).
5. Внизу слева в поле **Summary** напишите любой текст (например, `first version`) и нажмите синюю кнопку **Commit to main**.
6. Вверху нажмите **Publish repository**.
   - Галочку **Keep this code private** можно оставить включённой — репозиторий будет закрытым, это нормально.
   - Нажмите **Publish repository** ещё раз в окне.

Готово: код на GitHub.

## Часть 2. Развернуть на Railway

1. Откройте https://railway.app и нажмите **Login** → войдите через GitHub (**Login with GitHub**), разрешите доступ.
2. Нажмите **New Project**.
3. Выберите **Deploy from GitHub repo**.
4. В списке найдите репозиторий `wool-planning-server` и выберите его.
   - Если репозитория нет в списке — нажмите **Configure GitHub App** и дайте Railway доступ к нему.
5. Railway начнёт сборку по нашему `Dockerfile`. Подождите несколько минут, пока статус не станет **Success / Active**.

На этом сервис запущен, но пока без внешней ссылки — включим её в следующей части.

---

## Часть 3. Получить публичную ссылку

1. В проекте Railway кликните на сервис (плитку с названием), затем откройте вкладку **Settings**.
2. Найдите раздел **Networking** (или **Public Networking**).
3. Нажмите **Generate Domain**.
   - Если спросит порт — укажите **3001** (наш сервер слушает его по умолчанию; Railway также передаёт свой `PORT`, сервер это учитывает).
4. Появится адрес вида `https://wool-planning-production.up.railway.app`.

Откройте этот адрес в браузере — должно открыться приложение. Эту ссылку отправляйте команде. Она уже с **HTTPS**, поэтому кнопка «Копировать ссылку» и живая синхронизация работают как надо.

---

## Часть 4 (важно). Сохранять эталон между обновлениями

Накопленный эталон лежит в файле `data.json`. Без постоянного диска он может обнуляться при каждом обновлении. Подключаем диск один раз:

1. В сервисе Railway откройте **Settings → Volumes** (или кнопка **Add Volume** / **+ Volume**).
2. Создайте том с путём монтирования: `/data`
3. Перейдите на вкладку **Variables** и добавьте переменную:
   - **Name:** `DATA_FILE`
   - **Value:** `/data/data.json`
4. Сохраните. Railway перезапустит сервис. Теперь эталон и комнаты хранятся на постоянном диске и переживают любые обновления.

> В `Dockerfile` путь `/data/data.json` уже прописан по умолчанию, но переменную всё равно задайте явно — так надёжнее.

---

## Часть 5. Ограничить доступ (рекомендуется)

Инструмент внутренний, поэтому лучше закрыть его от посторонних. Самый простой способ на Railway — пароль на вход через готовый шаблон, либо доступ только по корпоративному VPN. Если нужен встроенный логин/пароль прямо в приложении — напишите мне, я добавлю простую защиту (Basic Auth) в сервер: тогда при открытии ссылки браузер будет спрашивать логин и пароль, которые вы зададите в переменных Railway.

---

## Как обновлять инструмент в будущем

1. Поменяйте нужные файлы в папке проекта у себя.
2. В GitHub Desktop: напишите Summary → **Commit to main** → вверху **Push origin**.
3. Railway сам заметит изменения и выкатит новую версию за пару минут. Ничего дополнительно нажимать не нужно.

---

## Если что-то пошло не так

- **Сборка упала (Build failed)** — откройте вкладку **Deployments → Logs** в Railway и пришлите мне последние строки лога, я подскажу причину.
- **Ссылка открывается, но белый экран** — обычно помогает обновить страницу; если нет — пришлите, что в консоли браузера (F12 → вкладка Console).
- **Данные (эталон) пропали после обновления** — не подключён том из Части 4, вернитесь к ней.
- **Нет репозитория в списке Railway** — в шаге выбора репо нажмите **Configure GitHub App** и дайте доступ именно к `wool-planning-server`.
