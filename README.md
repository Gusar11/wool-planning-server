# Wool & Hornet Planning (сервер)

Мультиплеерная версия покер-планирования: команды **Wool** и **Hornet**, независимые раунды по командам, кнопка «Завершить голосование» с записью в общий эталон, тултипы с последними эталонными задачами. Вся «правда» — на сервере, чужие голоса скрыты до раскрытия.

## Стек

- **Сервер:** Node.js + Express + Socket.IO
- **Клиент:** один `public/index.html` (тот же UI, что и в демо), подключается к серверу по веб-сокету
- **Хранилище:** `data.json` рядом с сервером (комнаты + общий эталон). Переживает перезапуск.

## Запуск локально

Нужен Node.js 18+.

```bash
npm install
npm start
```

Откройте http://localhost:3001 — это и есть приложение. Чтобы проверить мультиплеер, откройте ссылку комнаты в другом окне/браузере.

Порт и путь к данным настраиваются через переменные окружения:

```bash
PORT=8080 DATA_FILE=/var/data/wool.json npm start
```

## Как это работает

- Клиент раздаётся с того же адреса, что и сокет, — без CORS-настроек.
- Идентичность пользователя (`sessionId`, имя) хранится в `localStorage` браузера; всё общее состояние — на сервере.
- Сервер считает консенсус, раскрытие карт и запись в эталон сам: клиент не может подсмотреть чужие голоса до раскрытия или подделать эталон.
- Эталон общий и постоянный, пополняется при завершении голосования — только для голосовавшей команды.

## Сокет-события

Клиент → сервер: `room:create`, `room:enter`, `room:join`, `vote:submit`, `team:start`, `team:restart`, `team:finish`, `team:newround`.
Сервер → клиенту: `sync` (персонализированный вид комнаты + общий эталон).

## Деплой

Подойдёт любая платформа с постоянным процессом и веб-сокетами:

- **Railway / Render / Fly.io:** подключить репозиторий, команда старта `npm start`, платформа сама выставит `PORT`. Для сохранности данных смонтировать постоянный диск и указать на него `DATA_FILE` (иначе `data.json` потеряется при передеплое).
- **Свой VPS:** `npm ci`, запустить под `pm2` (`pm2 start server.js`), спереди Nginx как реверс-прокси с HTTPS (Let's Encrypt) и проксированием WebSocket.

Пример проксирования WebSocket в Nginx:

```nginx
location / {
    proxy_pass http://127.0.0.1:3001;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
}
```

## Что сделать перед боевым запуском

- **HTTPS** обязателен: без защищённого контекста не работают ни `navigator.clipboard` (кнопка «Копировать ссылку»), ни стабильный WebSocket.
- **Ограничить доступ:** VPN / Basic Auth на Nginx / SSO — инструмент внутренний.
- **Бэкап `data.json`** (в нём накопленный эталон — ценные данные).
- При росте нагрузки заменить файловое хранилище на БД (SQLite/Postgres) и, при нескольких инстансах, добавить Redis-адаптер для Socket.IO.
