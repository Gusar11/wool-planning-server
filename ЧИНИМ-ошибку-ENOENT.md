# Чиним ошибку «ENOENT: no such file or directory»

Эта ошибка означает: программа не нашла нужный файл. В 9 из 10 случаев причина — **терминал открыт не в той папке**, поэтому `npm start` не видит файл `package.json`. Ниже — как проверить и исправить за пару минут.

Сначала посмотрите на полный текст ошибки в терминале. Обычно там есть строка вида:

```
npm error enoent ENOENT: no such file or directory, open '...\package.json'
```

Если в конце упомянут `package.json` — это ровно наш случай (терминал не в той папке). Действуйте по шагам ниже.

---

## Шаг 1. Проверить, где сейчас «находится» терминал

Введите команду и нажмите Enter:

- **Windows:** `dir`
- **macOS:** `ls`

Появится список файлов текущей папки. Вам нужно увидеть в этом списке **`server.js`** и **`package.json`**.

- Если вы их **видите** — вы в правильной папке, переходите к Шагу 3.
- Если **не видите** (списка нет или там другие файлы) — терминал не в той папке. Идём в Шаг 2.

---

## Шаг 2. Зайти в правильную папку

1. Найдите папку `wool-planning-server` в Проводнике (Windows) или Finder (macOS).
2. В терминале наберите `cd`, поставьте пробел, затем **перетащите папку мышкой прямо в окно терминала** — путь подставится сам. Нажмите Enter.

Получится примерно так:

```
cd /Users/ivan/Desktop/wool-planning-server
```

3. Снова проверьте содержимое (`dir` на Windows или `ls` на macOS). Теперь `server.js` и `package.json` должны быть в списке.

> Если после `cd` терминал пишет, что папки не существует — значит при перетаскивании путь склеился неверно. Очистите строку и повторите: `cd` + пробел + перетащить папку.

---

## Шаг 3. Проверить, что папка не «вложенная»

Иногда при распаковке архива получается папка внутри папки, например:

```
wool-planning-server/
└─ wool-planning-server/     ← файлы лежат здесь, глубже
   ├─ server.js
   ├─ package.json
   └─ public/
```

Если на Шаге 1 вы видите **только одну вложенную папку** с тем же именем (а не `server.js`), зайдите в неё:

```
cd wool-planning-server
```

и снова проверьте (`dir` / `ls`). Файлы `server.js` и `package.json` должны оказаться прямо здесь.

Также убедитесь, что рядом с `server.js` есть папка **`public`**, а внутри неё — файл **`index.html`**. Проверить содержимое public:

- Windows: `dir public`
- macOS: `ls public`

Должен быть виден `index.html`. Если папки `public` или файла `index.html` нет — файлы распаковались не полностью, распакуйте архив заново целиком.

---

## Шаг 4. Установить зависимости и запустить

Находясь в правильной папке (где лежат `server.js` и `package.json`):

```
npm install
```

Дождитесь окончания (появится папка `node_modules`). Затем:

```
npm start
```

Должна появиться строка:

```
Wool & Hornet Planning слушает http://localhost:3001
```

Теперь откройте в браузере `http://localhost:3001`. Окно терминала не закрывайте — это работающий сервер.

## Быстрая шпаргалка «где я и что вокруг»

```
Windows:  cd            (показать текущий путь — введите: cd)
macOS:    pwd           (показать текущий путь)

Windows:  dir           (показать файлы вокруг)
macOS:    ls            (показать файлы вокруг)

cd путь                 (перейти в папку; путь удобно перетащить мышкой)
cd ..                   (подняться на одну папку вверх)
```

---

## Если ошибка ENOENT всё равно остаётся

Пришлите мне **полный текст** из терминала — скопируйте все строки, которые появились после `npm start` (особенно строки, начинающиеся с `npm error`). По ним я точно скажу, какого файла не хватает и что сделать. Также помогает ответ на вопросы:

- Какая система: Windows или macOS?
- Что показывает `dir` (Windows) или `ls` (macOS) в папке, откуда вы запускаете?
- Видно ли в этом списке `server.js`, `package.json` и папку `public`?
